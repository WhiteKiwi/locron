# Milestone 1 Acceptance Evidence

This matrix maps every completion criterion in [SPEC.md](SPEC.md) to exact tests registered by the
current workspace. It is evidence inventory, not a declaration that milestone 1 is complete.

Test names use `package/target: test-name`. Run one with, for example:

```sh
cargo test -p locron-core schedule::tests::spring_gap_is_absent_and_fall_fold_occurs_once
cargo test -p locron-cli --test cli due_one_time_job_catches_up_once_and_disables
```

`Covered` means the local automated tests directly exercise the criterion. `Partial` identifies a
remaining assertion or end-to-end gap. Every row remains `PENDING` for external evidence until the
current revision passes the official Linux/macOS architecture and process-lifetime matrix. Earlier
hosted runs cited in [STATUS.md](STATUS.md) do not cover the current test set or full architecture
matrix.

## Required external evidence

Before any row can be accepted for milestone 1, attach a current-revision CI or release-candidate run
covering Linux x86_64, Linux arm64, macOS x86_64, and macOS arm64. Each platform must record
`uname -a` and `rustc -vV`, then pass format, Clippy with `-D warnings`, and all workspace targets.
Criteria 8, 11, and 12 additionally require real process-tree, restart, and crash fixtures rather
than only deterministic in-process fault injection. Record failures as gaps; do not downgrade the
criterion or mark a row complete from an older commit.
